# 派活与审查模板（S0 配套）

主 agent 只做三件事：**定命题、派活、审查**。检索与作答由子 agent 完成，且必须过两道审查环。

```
主 agent ──派命题──▶ 答题子 agent（A）──自己检索+作答──▶ md 研究报告
                              ▲                              │
                              │ 退回修改（写明理由）          ▼
                        主 agent 现实审查 ◀──通过── 验证子 agent（B）交叉验证
                              │                              │
                              └──── 通过 ──▶ 进入拆树 / 估值
```

---

## 一、派活模板（主 agent → 答题子 agent，类型 A）

派活时必须给全五样，缺一样子 agent 就会自由发挥：

```
【命题】<一个能回答"是 / 否"或"多少"的命题，例如"2026 年行业产能收缩幅度是多少">
【要回答什么】<把命题拆成可直接回答的具体问题>
【需要的字段】每条数据都要：值 + 时点 + 来源 + 口径
【判据】<什么算回答成立；给区间还是点值>
【取数顺序】公司披露 > 官方统计 > 第三方汇编（P5）；政策一律读原文（S10）
【输出】md 研究报告，结构见下
【禁止】不得改动命题与判据；不得只给结论不给支撑；不得用媒体转述顶替原文
```

---

## 二、md 研究报告模板（答题子 agent，类型 A 产出）

**报告主体是"支撑信息"，不是结论。** 结论只有一句话，其余篇幅全部用来列支撑。

```md
# <命题>

## 结论
<一句话结论 + 关键数字；给区间就写区间>

## 支撑信息（逐条列全，这是报告的主体）
| # | 信息 | 值 | 时点 | 来源（名称 + 口径） | 等级 |
|---|---|---|---|---|---|
| 1 | ... | ... | ... | ... | 一手 / 二手 / 缺口 |

## 推理链
<从支撑信息到结论的每一步；能从现实一步算出的，不许加中间系数>

## 公司性质与驱动变量（命题涉及利润 / 收入 / 成本时必填）
<1) 这是什么性质的公司 / 行业；2) 该口径下利润实际由哪些变量驱动（量、价、成本、费用……）；3) 哪些项不适用、必须砍掉（如民生 / 免税行业无"税"，价格与成本强联动可合并成"价差"）；4) 建议下一层切哪几支。主 agent 据此直接 MECE，跳过恒等拆解层。>

## 数据缺口
<确实拿不到的，如实列出，不留空>

## 未决问题
<需要主 agent 裁定的>
```

---

## 三、交叉验证模板（主 agent → 验证子 agent，类型 B）

```
【任务】核验下列 md 报告中的每一条支撑信息是否真实
【要求】独立另找来源，**不得复用原报告引用的来源**；逐条判定，不给笼统结论
【输出】md：

| # | 原信息 | 独立来源 | 判定（属实 / 不属实 / 存疑） | 差异说明 |

## 总判定
通过 / 退回
## 退回清单（若有）
<逐条写明：哪条信息不实或存疑、依据是什么>
```

**判定规则**：只要有一条"不属实 / 存疑"，即退回原 A 修改，循环至全部属实。

---

## 四、现实审查清单（主 agent 亲自做，不可外包）

A 报告经 B 验证通过后，主 agent 逐条过一遍：

- **P5 三问**：口径对不对？时点是不是最近一期？机制还在不在？
- **P8 行为主体检验**：结论要求的主体行为，动机成立吗？（扩产要赚钱、退出要亏钱）
- **P9 溯源**：每个推算值能否当场答出出处？答不出的删掉或降级为假设。
- **恒等式勾稽**：与常识或恒等式冲突时，先怀疑数据（P7 二之二）。

不通过 → **写明理由退回原 A 修改**，循环至通过。**通过前，该命题的结论不得进入报告。**

---

## 五、并行与批次

- 同一层互不依赖的命题可**并行派发**；**同时最多 3 个子 agent**。
- 一个命题一个 A 子 agent；**验证 B 不得与 A 是同一个**（保持独立性）。
- **先派活、再动手**：分析阶段不临时补检索，需补则重新走本流水线。
