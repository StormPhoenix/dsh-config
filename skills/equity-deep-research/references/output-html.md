# HTML 输出规范

## 形式

- **单文件 HTML**，内联 CSS/JS，不依赖本地资源；图表库走 CDN
- 浅底深字，A 股口径红涨绿跌
- 文件名含股票名 + 日期，便于归档

## 章节结构（自上而下）

1. **头部**：标题 + 一句话方法口径 + **数据截止时点**
2. **首屏结论卡**：一句话本质 + 三个分叉各自的结论（当前价值 / 未来价值 / 炒作价值）+ 关键数字标签
3. **KPI 条**：股价 / 市值 / 估值 / 盈利收益率 / 股息率 / ROE
4. **三条主干各一节**（对应树的三个分叉），每节含：
   - **图形化树（SVG）**——见下方"树的图形规范"，不用文字缩进树代替
   - **图表**（驱动变量叠加、利润路径、因子排序等）
   - **结论框**
5. **数据核验表**：逐条列 值 / 来源 / 时点 / 等级（一手 / 二手 / 待确认 / 数据缺口）
6. **推算值溯源表**（P9 硬要求）：把每个**推算值**（预测价格 / 利润 / 产能、折现率、任何系数或折算率）单列一表，逐条写清**依据 + 时点**；答不出出处的必须删除，或显式降级为"情景假设"并写明依据
7. **免责声明**

## 树的图形规范

树必须**画成图**，不能用文字缩进树代替。

- 用 **SVG** 绘制：矩形节点框 + 连线，纵向分层；主干可横向分栏
- 每个节点框写两行：**命题**（主要）+ **关键数据**（小字）
- **叶子节点必须标注停下理由**，用颜色区分四类：
  - `触底` —— 再也问不出"由什么决定"
  - `数据缺口` —— 公开渠道确实拿不到
  - `已可操作` —— 已能给出量化判断
  - `判定无关` —— 连不回利润，已剪枝
- 被剪枝的分支：画到断点处用**虚线**收尾，并在断点旁写明理由
- 节点多时按主干拆成多张图，不要挤在一张

## 图表要求

- **叠曲线，不给孤立数字**：把指标与它的驱动变量画在一起（例：单位利润曲线 vs 原料成本指数；产品价格 vs 产能曲线）
- **不画中间比率**：PE、PB 之类的曲线一律不出现在图里；纵轴一律是利润或供需量
- 每张图配一句**读法**，说明它支持哪条结论
- 能画图就不写长表格；表格只用于多维对照
- 结论性的数字同时出现在图与文字里，避免只藏在一张图里

## 表达纪律

- 结论先行，再展开论证
- 每个数字标注来源与时点，区分一手 / 二手
- **P9：每个推算值都要能溯源**——报告里任何一个数字被追问"哪来的"，都要能立刻答出"来自哪份文件 / 哪个机制 / 哪条恒等关系"；答不出的就是凭空想象，删掉。**能从现实一步算出的，绝不多加一层中间比例（系数 / 折算率）**
- **一切预测自算**：不采用卖方预测作为结论或测算输入；卖方数据只能作"市场预期"参照，且必须标注"市场预期，不采用"
- 情景概率必须锚定可查证事实
- 正面表述：高估 / 合理 / 低估；衰退 / 低速增长 / 中速增长 / 高增长（禁"非 X"）
- 数据缺口如实列出，不硬凑
