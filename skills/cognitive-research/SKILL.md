# Cognitive Research — 认知路径调研写作框架

本 Skill 解决 AI 调研文章"零散知识点堆砌"的痛点，强制以**符合人类认知过程的叙事方式**组织和输出调研内容。

## 工作流阶段

| 阶段 | 说明 |
|------|------|
| `完整调研阶段 <topic>` | 启动认知路径调研，生成符合人类认知过程的调研文章 |
| `大纲阶段 <topic>` | 仅生成调研大纲，供用户确认后再展开 |
| `单节展开阶段 <section>` | 单独展开某一认知层次的内容 |

## 写作原则：五层认知路径

所有调研文章必须严格遵循以下五层结构，**由浅入深、层层递进**：

```
第一层：问题空间（Why does this exist?）
    ↓ 建立共鸣，让读者感同身受
第二层：核心直觉（What is the core idea?）
    ↓ 建立心智模型，类比优先
第三层：关键概念（How does it work?）
    ↓ 以点带面，每个概念有完整上下文
第四层：知识框架（How does it all connect?）
    ↓ 整合成可视化的关系网络
第五层：现实锚定（So what?）
    ↓ 落地场景 + 局限 + 延伸路径
```

## 完整调研阶段 完整流程

### 执行前：内化写作身份

在开始写作前，始终以如下身份定位自己：

> 你是一位刚刚深入研究了「{topic}」的记者/科普作家。你的读者是**聪明但完全不了解这个领域的人**。你写的每一句话都要经过一个内心检验：「我的读者能理解这个跳跃吗？」如果不能，就先铺垫，再展开。

### Step 1：问题空间（~200字）

**目标**：让读者在读第一段时就产生「啊，我懂这个痛苦」的共鸣。

**要求**：
- 用一个**具体的真实场景或困境**引入，不要用抽象定义开头
- 描述「在 {topic} 出现之前，世界是什么样的」
- 用 Before / After 对比结构，让问题的价值显而易见
- **禁止**用「{topic} 是一种...」的定义句开头

**示例模式**：
```
想象这样一个场景：[具体痛苦描述]。
这不是假设，这是 [领域] 从业者每天都在经历的困境。
直到 {topic} 出现，这个局面才开始改变。
```

### Step 2：核心直觉（~200字）

**目标**：用一句话 + 一个类比，让读者建立起对 {topic} 的基础心智模型。

**要求**：
- 先给出**日常生活中的类比**，再给出技术定义
- 类比必须能回答：「它的核心机制像什么？」
- 给出一句「电梯演讲」：如果只能说一句话，{topic} 是什么？
- **禁止**在没有类比铺垫的情况下直接引入专业术语

**示例模式**：
```
如果用一句话来描述，{topic} 就像是 [类比]。
更准确地说：[正式定义，此时读者已有直觉基础]。
这个设计的核心洞察是：[核心哲学/设计原则]。
```

### Step 3：关键概念（每个概念 ~150-200字）

**目标**：逐一展开 3-5 个核心概念，每个概念都有完整的认知上下文。

**要求**：
- 每个概念按固定模式展开（见下方模板）
- 概念之间必须有**显式的连接过渡句**（如：「理解了 A，就能更好地理解 B，因为...」）
- 新概念必须从已建立的概念中**生长出来**，禁止突然跳入新领域
- 每个概念必须包含**至少一个具体例子**，不得只有抽象描述

**单个概念展开模板**：
```
【概念名称】

没有它时：[缺失时会遇到什么问题/不便]
它是什么：[定义，尽量用上一步建立的类比来解释]
为什么这样设计：[设计动机，回答"为什么不用更简单的方式"]
具体例子：[一个可以操作/验证的真实案例]
与上一个概念的关系：[显式连接]
```

### Step 4：知识框架（~200字）

**目标**：将所有概念整合为一张读者能在脑海中"看见"的关系图。

**要求**：
- 用文字描述各概念之间的**依赖、影响、对比**关系
- 指出整个系统的「核心枢纽」是什么概念
- 说明数据/信息/控制流在这个系统中的流向
- 可用 ASCII 关系图辅助（如果能清晰表达的话）

**示例模式**：
```
现在让我们把所有概念放在一起看：
[概念A] 是基础，它决定了 [概念B] 的行为边界；
[概念C] 则是连接二者的桥梁，当 [触发条件] 时，
整个系统会按照 [流程描述] 运转。
```

### Step 5：现实锚定（~200字）

**目标**：让读者知道「学了这些，我能用来做什么，还需要注意什么」。

**要求**：
- 列举 2-3 个**最典型的真实使用场景**（不是功能列表，是场景故事）
- 诚实说明**已知局限和争议**（增加可信度）
- 提供清晰的**延伸学习路径**：下一步应该读什么、做什么

## 全局写作约束

### 禁止行为 ✗

- 禁止用**纯编号列表**堆砌知识点（可以有少量列表，但必须嵌入叙事上下文中）
- 禁止在**没有铺垫**的情况下引入新术语
- 禁止只给「是什么」而省略「为什么」和「具体例子」
- 禁止把文章写成**文档索引或功能说明书**
- 禁止各段落之间**没有过渡句**直接跳跃
- 禁止**以定义句开头**（「X 是一种 Y」型开头是知识堆砌的信号）

### 必须行为 ✓

- 每个新术语首次出现时，**必须附带类比或白话解释**
- 相邻段落/概念之间，**必须有显式连接词**：
  「因此」「这就导致了」「与此形成对比的是」「理解了这点，才能理解」「这里有一个微妙之处」
- 全文必须有一条清晰的**叙事主线**，读者能感受到文章在"走向某个地方"
- 结尾必须给出**明确的行动锚点**（读者下一步能做什么）

### 写作风格

- **目标读者**：聪明但完全不了解该领域的人（「好奇的外行」）
- **写作形式**：散文叙事 + 必要结构的混合体（非纯文档式）
- **类比原则**：类比优先，术语其次；类比应来自日常生活，而非其他专业领域
- **语气**：像一位真诚的专家朋友在讲解，而不是一份官方报告

## 输出格式模板

```markdown
# {Topic}：[一句能让外行产生好奇心的副标题]

> **一句话**：{topic} 就像是 [类比]，专门用来解决 [核心问题]。

## 从一个真实的困境说起

[第一层：问题空间，~200字，场景叙事]

## 它的核心思路是什么

[第二层：核心直觉，~200字，类比 + 一句话定义]

## 深入理解：三个关键概念

### [概念一名称]
[按概念模板展开，~150-200字]

### [概念二名称]
[显式过渡句] + [按概念模板展开，~150-200字]

### [概念三名称]
[显式过渡句] + [按概念模板展开，~150-200字]

## 全局视图：概念如何连接成系统

[第四层：知识框架，~200字]

## 在现实中，它是怎么用的

[第五层：现实锚定，~200字，场景故事而非功能列表]

## 它解决不了什么

[已知局限与边界，~100字，增加可信度]

## 如果你想深入

[延伸学习路径，具体可操作的下一步]
```

## 适用场景

- **新代码仓库理解**：「帮我调研 LangGraph 这个库」
- **新技术进展**：「帮我了解 Diffusion Transformer 的最新进展」
- **领域入门**：「帮我调研强化学习领域」
- **工具评估**：「帮我了解 Temporal 工作流引擎」
- **概念澄清**：「帮我深入理解 RAG 和 Fine-tuning 的区别」

### 示例对话

- "帮我调研一下 LangGraph" → `完整调研阶段 "LangGraph"`
- "我想深入了解 Rust 的所有权模型" → `完整调研阶段 "Rust 所有权"`
- "帮我写一篇关于 MCP 协议的调研文章" → `完整调研阶段 "MCP 协议"`
- "先给我看看大纲" → `大纲阶段 "主题"`

## 注意事项

- 文章总长度建议 1500-3000 字，过短则深度不足，过长则容易失去叙事节奏
- 如果主题过于宽泛（如「人工智能」），应先询问用户缩小范围，再开始写作
- 如果需要引用最新信息，应配合 `web_search` 工具 先收集材料，再用本框架组织输出
- 概念数量建议 3-5 个，过多会破坏叙事节奏；如需涵盖更多，可在"延伸学习"中列出
